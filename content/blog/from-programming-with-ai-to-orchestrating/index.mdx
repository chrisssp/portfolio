# De programar con IA "porque sí" a orquestar mi código

"¿Usas IA para programar? Entonces no sabes programar". Esa frase la escuché innumerables veces desde que la IA se posicionó como un antes y un después en el desarrollo de software.

Soy ingeniero de software recién egresado, crecí a la par de la IA. Al principio usaba GitHub Copilot con el plan de estudiantes, pero los tokens se me iban volando: no sabía qué modelo usar para cada tarea, o simplemente me olvidaba de cambiar. Terminaba usando GPT-4o para preguntas exploratorias que bien podía resolver con algo más ligero.

## El cambio de paradigma

Después de un par de años codeando sin una estructura clara, conocí **Gentle AI**, el ecosistema de [Alan Buscaglia](https://www.linkedin.com/in/alanbuscaglia). No es solo "otro asistente": es un configurador que se integra con tu agente favorito (yo uso OpenCode).

## ¿En qué se nota la diferencia?

Toda la respuesta se sostiene sobre tres pilares, y son estos:

### 1. Engram
Memoria persistente entre sesiones. Tu agente recuerda decisiones, bugs y contexto sin repetir todo.

### 2. SDD
Una metodología que estructura el trabajo en fases: exploración, diseño, implementación, verificación.

### 3. Model routing
Elegir el modelo exacto para cada fase. Yo uso Gemini 3.6 Flash para explorar y Claude Sonnet 5 para diseñar.

Eso cambió todo. Los tokens rinden más, el código es más consistente, y hay un proceso detrás, no solo prompts al azar.

## Pasé de ejecutor a orquestador

Pero lo importante es cómo me hizo sentir: pasé de usar IA sin dirección a sentirme un **orquestador**. Alguien que define el rumbo, supervisa cada etapa y toma decisiones arquitectónicas mientras la IA ejecuta.

La IA no te reemplaza. Te potencia. Pero solo si tienes un proceso, no simplemente un chat.

# From coding with AI "just because" to orchestrating my code

"You use AI to code? Then you don't really know how to program." I've heard that phrase countless times since AI positioned itself as a before-and-after moment in software development.

I'm a freshly graduated software engineer who grew up alongside AI. At first, I used GitHub Copilot with the student plan, but my tokens were flying away: I didn't know which model to use for each task, or I simply forgot to switch. I'd end up using GPT-4o for exploratory questions that I could easily solve with something lighter.

## The paradigm shift

After a couple of years coding without a clear structure, I discovered **Gentle AI**, the ecosystem by [Alan Buscaglia](https://www.linkedin.com/in/alanbuscaglia). It's not just "another assistant": it's a configurator that integrates with your favorite agent (I use OpenCode).

## Where does the difference show up?

The whole answer rests on three pillars, and here they are:

### 1. Engram
Persistent memory across sessions. Your agent remembers decisions, bugs, and context without repeating everything.

### 2. SDD
A methodology that structures work into phases: exploration, design, implementation, verification.

### 3. Model routing
Choose the exact model for each phase. I use Gemini 3.6 Flash for exploration and Claude Sonnet 5 for design.

That changed everything. Tokens go further, code is more consistent, and there's a process behind it—not just random prompts.

## From executor to orchestrator

But what matters most is how it made me feel: I went from using AI without direction to feeling like an **orchestrator**. Someone who sets the direction, oversees each stage, and makes architectural decisions while AI executes.

AI doesn't replace you. It empowers you. But only if you have a process, not just a chat.
